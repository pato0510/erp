# FIN-005 — Definir navegación, flujos y propuesta de experiencia de uso

**Tipo:** Ticket de arranque.  
**Estado inicial:** PROPUESTO.  
**Dependencias:** FIN-004.  
**Referencias:** F03–F15; D-003, D-008 y componentes existentes.

**Coordinación vigente:** el director prepara el prompt y revisa el resultado; CC realiza las inspecciones o modificaciones del repositorio y devuelve evidencia. Patricio lleva el encargo y comparte el informe. Ver `03_PROTOCOLO_DIRECTOR_CC.md`.

## Resultado esperado

Acordar cómo se usará el nuevo módulo dentro del ERP, con recorridos completos y una propuesta visual revisable.

## Trabajo

1. Analizar navegación, componentes y patrones actuales. Definir entradas, jerarquía, listados, detalle y continuidad entre Finanzas y otros módulos.
2. Especificar los recorridos prioritarios y las diferencias entre datos pendientes, clasificados, conciliados, vencidos y proyectados.
3. Preparar wireframes o prototipo de alcance acotado con datos ficticios, según herramientas disponibles. Mostrar carga, vacío, error, permisos y acciones de corrección relevantes.
4. Relacionar la propuesta con comportamientos observados de itSave y con requisitos propios. Resolver con Patricio la fidelidad deseada y las adaptaciones al ERP.

## Entregables

ESPECIFICACION_UX.md y propuesta visual revisable o equivalente. El formato se elige con el proyecto; un prototipo no se presenta como módulo implementado.

Las rutas documentales se adaptan a la ubicación adoptada en FIN-000. Reutilizar resultados existentes que cumplan estos criterios.

## Criterios de aceptación

- [ ] Flujos prioritarios tienen inicio, acciones, resultado, correcciones y acceso desde el ERP.
- [ ] La propuesta expresa los estados financieros sin ambigüedad y contempla sus excepciones principales.
- [ ] Reutilización de componentes y diferencias frente a itSave están documentadas.
- [ ] Patricio puede revisar la propuesta; decisiones pendientes de experiencia permanecen visibles.

## Verificación

Recorrer los flujos con escenarios representativos y comprobar que cada acción tenga un resultado especificado. Verificar legibilidad y adaptaciones de pantalla pertinentes al uso real.

## Bloqueos y límites

Sin evidencia privada se puede proponer UX, pero no declarar fidelidad comprobada a itSave. No modificar lógica operativa para producir el prototipo.

Este ticket no autoriza cambios en la lógica de negocio ni efectos sobre datos reales. Los prototipos de FIN-005 son propuestas aisladas. Si el usuario ya autorizó otro alcance, registrarlo por separado y conservarlo.
