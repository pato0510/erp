# FIN-000 — Recibir el traspaso y establecer continuidad

**Tipo:** Ticket de arranque.  
**Estado inicial:** LISTO.  
**Dependencias:** ninguna.  
**Referencias:** Contexto del usuario y documentos del traspaso.

**Coordinación vigente:** el director prepara el prompt y revisa el resultado; CC realiza las inspecciones o modificaciones del repositorio y devuelve evidencia. Patricio lleva el encargo y comparte el informe. Ver `03_PROTOCOLO_DIRECTOR_CC.md`.

## Resultado esperado

Reconocer el proyecto correcto y adoptar un registro de trabajo que aproveche el contexto y los avances existentes.

## Trabajo

1. Leer el traspaso, las instrucciones locales y la documentación relevante. Identificar la raíz real del ERP y su sistema de tareas.
2. Registrar rama, commit y cambios existentes si Git está disponible. Identificar avances previos de Finanzas y su evidencia sin atribuirse trabajo ajeno.
3. Elegir una sola ubicación de control. Adaptar o incorporar estado, decisiones y backlog sin duplicar registros existentes. Conservar el reporte de investigación como antecedente.
4. Revisar las respuestas ya disponibles a D-001, D-002 y D-003. Preguntar solo lo que falte y no pueda obtenerse del proyecto.

## Entregables

Estado inicial actualizado, ubicación del control, correspondencia de tickets y referencias al trabajo previo.

Las rutas documentales se adaptan a la ubicación adoptada en FIN-000. Reutilizar resultados existentes que cumplan estos criterios.

## Criterios de aceptación

- [ ] Repositorio e instrucciones aplicables identificados; limitaciones de acceso expresas si las hubiera.
- [ ] Una ubicación de control y una fuente principal de estado adoptadas, con referencias funcionales.
- [ ] Trabajo previo reconocido y preguntas ya respondidas reutilizadas.
- [ ] FIN-001 preparado como siguiente candidato, o alternativa justificada por el estado real.
- [ ] Ninguna modificación de lógica de negocio atribuida a este ticket documental.

## Verificación

Revisar consistencia de rutas, IDs, estados y referencias; contrastar con Git. No ejecutar suites completas por importar documentación.

## Bloqueos y límites

Si el proyecto no está accesible o no es el indicado, solicitar la ruta correcta. La falta de acceso privado a itSave no bloquea este ticket.

Este ticket no autoriza cambios en la lógica de negocio ni efectos sobre datos reales. Los prototipos de FIN-005 son propuestas aisladas. Si el usuario ya autorizó otro alcance, registrarlo por separado y conservarlo.
