# FIN-007 — Planificar integraciones y transición de datos

**Tipo:** Ticket de arranque.  
**Estado inicial:** PROPUESTO.  
**Dependencias:** FIN-006.  
**Referencias:** D-001, D-006, D-009, D-010; integraciones actuales y reglas de consistencia.

**Coordinación vigente:** el director prepara el prompt y revisa el resultado; CC realiza las inspecciones o modificaciones del repositorio y devuelve evidencia. Patricio lleva el encargo y comparte el informe. Ver `03_PROTOCOLO_DIRECTOR_CC.md`.

## Resultado esperado

Definir cómo incorporar fuentes y servicios externos y cómo pasar del módulo actual al nuevo preservando la operación necesaria.

## Trabajo

1. Inventariar conectores existentes y los que falten para bancos, documentos, emisión, IA, MCP y canales según alcance. Identificar proveedor, contrato, acceso, sandbox y restricciones reales.
2. Definir normalización, identidad, deduplicación, sincronización, errores, reintentos, trazabilidad y datos antiguos para cada integración aplicable.
3. Resolver la estrategia de preservación a partir de D-001: mapeo, saldos, asociaciones, permisos, ensayo, validación y reversión. No asumir que se puede vaciar la base.
4. Evaluar convivencia, activación gradual y retirada del módulo anterior. Precisar fuente de verdad y evitar doble escritura o doble conteo.
5. Separar diseño de conectores, simulación, validación con proveedor y operación real; trasladar dependencias externas a tickets concretos.

## Entregables

PLAN_INTEGRACIONES.md y PLAN_TRANSICION.md con condiciones de entrada, comprobaciones, decisiones y límites de operación.

Las rutas documentales se adaptan a la ubicación adoptada en FIN-000. Reutilizar resultados existentes que cumplan estos criterios.

## Criterios de aceptación

- [ ] Cada integración del alcance tiene mecanismo, dependencia y forma de validación identificados o una investigación pendiente explícita.
- [ ] El plan distingue sincronización y emisión de lectura o simulación.
- [ ] Preservación y conciliación de datos tienen una estrategia verificable acorde a lo que se conoce.
- [ ] La transición identifica fuente de verdad, compatibilidad, ensayo, reversión y criterios de activación.
- [ ] No se atribuye autorización para contratos, emisiones o producción al trabajo documental.

## Verificación

Revisar cobertura de fallos y recuperación; recorrer reintentos y duplicados sobre el diseño. Contrastarlo con proveedores y datos realmente disponibles sin ejecutar efectos reales.

## Bloqueos y límites

D-001 sin resolver impide cerrar una estrategia definitiva para datos reales. Pueden prepararse alternativas. Sin proveedor se puede planificar el adaptador, dejando la integración real pendiente.

Este ticket no autoriza cambios en la lógica de negocio ni efectos sobre datos reales. Los prototipos de FIN-005 son propuestas aisladas. Si el usuario ya autorizó otro alcance, registrarlo por separado y conservarlo.
