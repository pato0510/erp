## Notes

- **Total operations migrations:** 20 (out of ~40 total in the database including platform).
- **All migrations are forward-only.** No down migrations. To roll back, restore from a point-in-time backup.
- **Naming convention:** `YYYYMMDDhhmmss_<verb>_<noun>` in snake_case. Sprint 8 migrations use 1400+ timestamps to leave room for parallel hotfixes.
- **RLS posture:** Every operations table enables RLS with a `current_setting('rls.company_id')`-based policy. The migrator role has `BYPASSRLS`; the application role does not. Materialized views are an exception (PG limitation) — the application enforces tenancy at the query layer.
- **Audit triggers:** Every operations table has an `audit_trigger_function()` AFTER INSERT/UPDATE/DELETE trigger writing to `audit_logs` (defined in the platform-level `add_audit_triggers` migration).
- **Schema layout:** Single `operations.prisma` file under `apps/api/prisma/schema/` (Prisma's `prismaSchemaFolder` mode). Total schema length at module close: ~1170 lines.
